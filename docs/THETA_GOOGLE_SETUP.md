# Theta Hatch シリーズ Google連携の設定（共通と、アプリごと）

Google Cloud の設定は **シリーズで1つのプロジェクト** にまとめます。
ほとんどは最初の1回（Theta Meishi Hatch で済んでいます）だけで、アプリを増やすたびに必要なのは **Android用OAuthクライアントの追加だけ** です。

画面は https://console.cloud.google.com/ で、上部のプロジェクト選択がシリーズのプロジェクトになっていることを確かめてから操作します。
左のメニューの「Google Auth Platform」（古い表示では「APIとサービス」→「OAuth同意画面」「認証情報」）が OAuth の設定です。

## 共通（1回だけ。Meishi で済み）

1. **プロジェクト**：シリーズで1つ。名前は何でもよい（例 `theta-hatch`）。既に `meishi-claude` などで作ってあればそのまま使う。
2. **API の有効化**：「APIとサービス」→「ライブラリ」。API はプロジェクト全体で有効になるので、2つ目のアプリで同じ API を使うなら何もしなくてよい。
   - Google Drive API：Theta Vault の同期、ドライブのフォルダからの取り込み（全アプリ）
   - Google People API：**Web版**で Google 連絡先に登録するとき（Android は端末の連絡先アプリ経由なので不要）
   - Google Calendar API：**Web版**でカレンダーに書くアプリができたとき（Android は端末のカレンダー経由なので不要）
3. **同意画面**（Google Auth Platform →「ブランディング」「対象」）：アプリ名、サポートメール、対象は「外部」、公開ステータスは「テスト」のまま。
4. **テストユーザー**（Google Auth Platform →「対象」→「テストユーザー」）：`kiwiman0706@gmail.com`。
   **プロジェクトに1回だけ**で、アプリを増やすたびに確かめる必要はありません（同じプロジェクトの全アプリに効きます）。
   追加が要るのは、別の Google アカウントで使うとき・家族など他の人にも使ってもらうときだけ（最大100人）。
5. **Web用OAuthクライアント**（Web版を使う場合）：「クライアント」→「クライアントを作成」→ 種類「ウェブ アプリケーション」、承認済みの JavaScript 生成元 `https://kiwiman0706-beep.github.io`。
   生成元はドメインまでで、リポジトリ名（`/MeishiApp/` など）は含まないので、**シリーズの Web版はすべてこの1つのクライアントIDを共用** できます。
   クライアントIDは各アプリの「シリーズの設定」（`google.webClientId`）で引き継がれます。

### おすすめ：同意画面のアプリ名を「Theta Hatch」に

許可画面に出るアプリ名は、プロジェクトに1つです（アプリごとではありません）。
`Theta Meishi Hatch` のままだと、他のアプリで許可するときにも「Theta Meishi Hatch がアクセスを求めています」と出ます。
「ブランディング」でアプリ名を `Theta Hatch` に変えておくと、どのアプリでも自然に読めます（変えても Meishi の動作には影響しません）。

## アプリごと（アプリを増やすたび）

### 1. パッケージ名と SHA-1 を確かめる

| 取り方 | パッケージ名 | SHA-1 |
| --- | --- | --- |
| **アプリの画面**（いちばん確実） | 初期設定ガイドに表示（コピーボタン付き） | 同じく表示。インストールされているアプリの署名から読むので間違いがない |
| GitHub のリポジトリ | `android/app/build.gradle` の `applicationId` | ファイルには無い（署名鍵は Secret なので見えない） |
| Claude に聞く | `applicationId` を答えられる | APK か署名鍵があれば `apksigner` / `keytool` で出せる |

- **コンソールに入れる SHA-1 は、そのアプリの初期設定ガイドに出る値を使ってください**（インストールされているアプリ自身の署名から読むので確実です）。
- Meishi の署名鍵（`meishiclaude-release.jks`）の SHA-1 は次のとおりです（鍵とリリース版の APK で確認済み）：

  ```
  A1:13:EA:34:83:60:56:32:E7:F5:94:4E:4E:8C:20:55:DD:AE:28:BA
  ```

  他のアプリもこの鍵で署名すれば同じ値になります。ただし、**そのアプリの開発スレッドで別の鍵を作っていたり、デバッグ版だったりすると違う値になります**。その場合は、ガイドに出る値で登録すれば動きます。
  シリーズで揃える場合は、新しいアプリのビルドにも Meishi の鍵を渡してください（APIキーの貸し借り（`SeriesProvider`）は、同じ鍵で署名したアプリ同士でしか動きません）。
- パッケージ名は新しいアプリなら `jp.yaegaki.theta.<名前>` です（Meishi だけは歴史的事情で `jp.yaegaki.meishiclaude`）。
- Android Studio から直接入れた**デバッグ版**は、パソコンのデバッグ用の鍵で署名されるため SHA-1 が違います。デバッグ版で Google ログインを試すときだけ、そのSHA-1でもう1つクライアントを作ります（GitHub のリリース版だけ使うなら不要）。

### 2. Android用OAuthクライアントを作る

Google Auth Platform →「クライアント」→「クライアントを作成」：

1. アプリケーションの種類：**Android**
2. 名前：`Theta <名前> Hatch Android` など（自分が見分けるためだけ）
3. パッケージ名：上の値
4. SHA-1 証明書フィンガープリント：上の値
5. 作成。クライアントIDをアプリに入力する必要はありません（Google がパッケージ名と署名で見分けます）。

反映に数分かかることがあります。これで、そのアプリの「Google Driveで同期を始める」が通ります。

### 3. そのアプリが新しい API を使うなら

上の「共通」2 で有効にします（プロジェクトに1回）。新しい種類の許可（例：カレンダー）を使う場合は「データアクセス」にもスコープを足しておくと、許可画面の説明が正しくなります（無くても動きます）。

## 知っておくこと

- **「このアプリはGoogleで確認されていません」**：自分で作ったテスト中のアプリなので「続行」で問題ありません。
- **テスト中は、許可が7日ほどで切れることがあります**（Google の仕様）。その時は同期や取り込みのボタンを押すと許可画面がもう一度出るので「許可」を押します。
  これを無くすには公開（本番）にする必要がありますが、ドライブ全体へのアクセスは Google の審査（セキュリティ評価）が必要な種類のため、**個人で使う間は「テスト」のままがおすすめ** です。
- **うまくいかないとき**（アカウントを選んだ後、何も起きずに戻る）は、ほとんどが「Android用クライアントのパッケージ名か SHA-1 の違い」か「テストユーザーに入っていない」です。アプリの初期設定ガイドの値と、コンソールの値を見比べてください。
- 鍵を作り直した（SHA-1 が変わった）場合は、**全アプリ** の Android用クライアントの SHA-1 を直す必要があります。鍵は作り直さないでください。
