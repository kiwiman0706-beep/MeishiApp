# Theta Meishi Hatch インポートファイル仕様 v1

Theta Meishi Hatch（名刺管理アプリ）の「メニュー → ZIPから一括取り込み」で読み込めるファイルの仕様です。
この仕様どおりのZIPを作れば、名刺データと名刺画像をまとめて登録できます。

---

## 1. ファイル構成

拡張子 `.zip` のファイル1つ。中身は **CSV 1つ** と **画像ファイル** です。

```
meishi-import.zip
├── cards.csv
└── images/
    ├── 00001.jpg
    ├── 00002.jpg
    └── ...
```

- CSVのファイル名は `cards.csv` を推奨します。ZIP内にCSVが複数ある場合は `cards.csv` を使い、無ければ見つかった最初のCSVを使います。
- 画像フォルダの名前と階層は自由です。CSVには **CSVファイルの場所から見た相対パス** で画像を書きます（例：`images/00001.jpg`）。
- ZIP内のパスはASCII（英数字・`_`・`-`・`.`・`/`）を推奨します。
- `__MACOSX/` 以下は無視します。

## 2. CSVの形式

| 項目 | 規則 |
| --- | --- |
| 文字コード | UTF-8（BOMあり推奨）。Shift_JIS（CP932）も可（自動判別） |
| 改行 | CRLF または LF |
| 区切り | カンマ `,` |
| 引用 | 値にカンマ・改行・`"` を含む場合は `"` で囲み、値の中の `"` は `""` と書く（RFC 4180） |
| 1行目 | 見出し行（必須） |
| 2行目以降 | 1行 = 1人 |
| 列の順番 | 自由 |
| 知らない列 | 無視する |
| 空の行 | 無視する |
| 行数の上限 | 20,000行 |

## 3. 列の定義

見出しには下表の **列名** をそのまま使ってください。どの列も省略できます（ただし「氏名」か「表面画像」のどちらかは入れてください）。

| 列名 | 内容 | 書き方 |
| --- | --- | --- |
| `ID` | その人を識別する文字列 | 任意。入れておくと、同じZIPを再読み込みしても二重登録されません（§5） |
| `氏名` | 氏名 | 例：`山田 太郎` |
| `ふりがな` | 読み | 例：`やまだ たろう` |
| `会社名` | 会社・組織名 | |
| `部署` | 部署名 | |
| `役職` | 肩書き | |
| `メール` | メールアドレス | 複数ある場合はセル内で改行して並べる |
| `電話` | 会社の電話番号 | 複数ある場合はセル内で改行 |
| `携帯電話` | 携帯番号 | 複数ある場合はセル内で改行 |
| `FAX` | FAX番号 | |
| `郵便番号` | 郵便番号 | 例：`100-0001` |
| `住所` | 住所 | 1つのセルに全部入れる |
| `Webサイト` | URL | |
| `タグ` | 分類 | 自由文字列 |
| `名刺交換日` | 名刺交換した日 | `YYYY-MM-DD` 推奨。`YYYY/M/D`、`YYYY年M月D日` も可。解釈できない値は空になる |
| `交換場所` | 出会った場所 | |
| `メモ` | やり取りのメモ | 1セル = メモ1件。複数のメモは `メモ` 列を複数作る（同じ見出しを繰り返してよい） |
| `表面画像` | 名刺表面の画像 | CSVからの相対パス |
| `裏面画像` | 名刺裏面の画像 | CSVからの相対パス |
| `追加画像` | その他のページ | CSVからの相対パス。複数あれば `追加画像` 列を繰り返す |

補足：

- 同じ項目に当たる列が複数ある場合、`住所` は空白で、それ以外は改行でつないで1項目に入れます（`メモ`・`追加画像` だけは列ごとに別の1件として扱います）。
- 値の前後の空白は取り除きます。
- 姓と名が別々なら、`姓`・`名` 列（ふりがなは `姓(カナ)`・`名(カナ)` 列）でも構いません。「姓 名」の形につなげます。`氏名` 列がある場合はそちらを優先します。

## 4. 画像

| 項目 | 規則 |
| --- | --- |
| 形式 | JPEG / PNG / WebP / HEIC / PDF（PDFは全ページを取り込む） |
| 1ファイルの上限 | 100MB |
| 向き | EXIFの回転情報に従う |
| パスの照合 | 大文字小文字を区別しない。`\` 区切りも可。CSVからの相対パスで見つからない場合は、ZIPのルートからのパスとして探す |
| 見つからない画像 | その画像だけ飛ばし、取り込み結果にエラーとして表示する（その人は登録される） |

ページの順番は `表面画像` → `裏面画像` → `追加画像`（列の左から順）です。

## 5. 取り込み時の動き

| 行の内容 | 結果 |
| --- | --- |
| `氏名` あり | CSVの値で登録し、状態は「確認済み」。画像はそのまま保存し、Geminiには送らない |
| `氏名` なし・画像あり | 画像を保存し、バックグラウンドでGeminiが読み取って項目を埋める |
| 認識できる値が1つも無い行 | 読み飛ばす |
| 既に取り込んだ人 | 追加しない |

「既に取り込んだ人」は次のキーで判定します。

- `ID` 列がある場合：`ID` の値
- ない場合：`氏名`＋`会社名`＋`メール`＋`表面画像` の組み合わせ

読み込む時に「Google連絡先にも登録する」をオンにすると、氏名のある人をバックグラウンドでGoogle連絡先にも登録します。

## 6. 全上限

| 項目 | 上限 |
| --- | --- |
| ZIPファイル | 4GB |
| ZIP内のファイル数 | 50,000 |
| CSV | 64MB、20,000行 |
| 画像1枚 | 100MB |

## 7. 例

`cards.csv`（UTF-8 BOM付き）：

```csv
ID,氏名,ふりがな,会社名,部署,役職,メール,電話,携帯電話,住所,名刺交換日,交換場所,タグ,メモ,表面画像,裏面画像
c0001,山田 太郎,やまだ たろう,サンプル株式会社,営業部,部長,taro@example.com,03-1234-5678,090-1234-5678,東京都千代田区丸の内1-1-1,2024-03-05,展示会,取引先,次回見積もり送付,images/00001.jpg,images/00002.jpg
c0002,佐藤 花子,,テスト商事,,代表取締役,"hanako@example.com
info@example.com",,,,2023-11-20,,,,images/00003.jpg,
c0003,,,,,,,,,,,,,,images/00004.jpg,images/00005.jpg
```

- 1行目：全項目＋表裏の画像。
- 2行目：メールが2つ（セル内改行のため `"` で囲む）。裏面なし。
- 3行目：画像だけ。取り込み後にGeminiが読み取ります。

## 8. 画像だけのZIP（CSVなし）

ZIPにCSVが無い場合は、画像のファイル名で1人ずつにまとめます。氏名などの項目は、取り込み後にGeminiが読み取ります。

| ファイル名の形 | まとめ方 |
| --- | --- |
| `YYYYMMDD_氏名_会社名_数字ID.jpg`／`…_数字ID_裏.jpg`（Eightの画像ダウンロード） | 同じIDを1人に（表→裏）。氏名・会社名・名刺交換日をファイル名から入れる（会社名の `__` は空白に） |
| `キー_1`／`キー_2`（`-1`/`-2`、`_表`/`_裏`、`_front`/`_back` も可） | 同じフォルダ・同じキーを1人に（1・表 → 2・裏 → 3 → 4） |
| 上記以外 | 1枚 = 1人 |

- ZIP内のファイル名はUTF-8でもShift_JIS（Windowsで作ったZIP）でも読めます。
- 二重取り込みの判定キーは、EightのIDか「フォルダ＋キー」です。

## 9. 作成時のチェックリスト

- [ ] ZIPの中に `cards.csv` と画像がある
- [ ] CSVの1行目が見出しで、列名が§3の表どおり
- [ ] UTF-8（BOM付き）で保存している
- [ ] カンマ・改行を含む値を `"` で囲んでいる
- [ ] `表面画像` などのパスが、ZIP内の実際のファイルと一致している
- [ ] 各行に `氏名` か `表面画像` の少なくとも一方がある
- [ ] 再読み込みの可能性があるなら `ID` 列を入れている
